ToolBox Vol. 1/Standalone Tools/Lifetime Track Manual

Lifetime Track Manual

GameObject and asset lifecycle tracker identifying persistent memory leaks, post-mortem dangling C# references, scene teardown leaks, and unreleased pooling allocations.

Access & Launch

  • Menu Path: Tools > Maharaja Studio > MSUltimate > ToolBox Vol 1 > Object Lifetime Tracker
  • In-Game Runtime HUD Overlay: Hotkey F8 or 3-finger mobile touch gesture (Console: lifetime.hud).

Capabilities & Workflows

1. Post-Mortem Dangling Reference Hunter

  • The Problem: Calling Destroy(gameObject) destroys the native C++ engine object (m_CachedPtr == 0), but static events (GameEvents.OnScoreChanged += HandleScore), singletons, or living managers retaining a C# reference keep the entire managed wrapper, its fields, arrays, and textures alive in the Mono/IL2CPP heap forever.
  • The Solution:
    • Retains a WeakReference<object> on OnDestroy().
    • Audits surviving references where target != null && (UnityEngine.Object)target == null.
    • Flags dead instances with ⚠ DANGLING alerts in the inspector and tables.
    • One-click "Inspect Retainers" button scans static event delegates, collections, and living scene MonoBehaviour fields to pinpoint the exact leak source holding the dead object.

2. Scene Teardown & Transition Audit

  • The Problem: GameObjects and pooled instances often fail to clean up during scene changes, leaking past scene unloads or PlayMode transitions.
  • The Solution:
    • Automated hooks into SceneManager.sceneUnloaded and EditorApplication.playModeStateChanged (ExitingPlayMode).
    • Any instance belonging to the unloaded scene that is still marked alive is automatically flagged as a teardown leak (🚨 LEAKED).
    • Generates formatted audit reports to console and UI:

"3 instances leaked past Scene 'Level_01' unload! (2x EnemyBullet, 1x FloatingDamagePopup). Alive duration: 240s."

3. Differential Snapshot Engine (Baseline Diffing A vs B)

  • The Problem: Cumulative session counters make it difficult to isolate leaks caused by a specific gameplay action (e.g., Opening Inventory, Completing Wave 3, or Replaying a Match).
  • The Solution:
    • Set Baseline (Snapshot A): Freezes all current type and global active counts as the reference state.
    • Live Delta Tracking: Real-time columns for ΔActive, ΔSpawn, ΔKill, Net Leak, and ΔRAM.
    • Types with positive active deltas or unreleased net counts upon returning to an idle state are highlighted in bright red as verified leaks.

4. Interactive Timeline & Range Slicing

  • Real-time rolling/sliding window painter (Last 10s, 30s, 60s, 2m, 5m, Full Session).
  • Zoom with mouse wheel, pan with Middle/Right/Alt drag, and click-and-drag to slice time windows for targeted anomaly inspection.

ToolBox Vol. 1/Standalone Tools/Live Track Manual

Live Track Manual

Autonomous real-time variable telemetry, multi-scale oscilloscopes, and in-SceneView floating HUDs for Unity runtime diagnostics.

Access & Launch

  • Menu Path: Tools > Maharaja Studio > MSUltimate > ToolBox Vol 1 > LiveTrack Dashboard

Capabilities & Workflows

1. Autonomous Background Sampling Engine

  • Decoupled from Inspector: Telemetry sampling runs continuously in the background across all active scene objects via LiveTrackRegistry. Objects continue streaming data even when unselected or when the Inspector is viewing another GameObject.
  • Scene-Wide Auto-Discovery: Discovers all MonoBehaviours decorated with [LiveTrack] automatically upon window focus or scene changes.

2. Multi-Scale Y-Axis Display Modes

  • Combined Mode (Absolute): Global shared scale for comparing metrics with identical units (e.g., Vector3 components or multiple temperature sensors).
  • Normalized Mode (0% – 100%): Per-series dynamic normalization, allowing simultaneous comparison of wildly mismatched orders of magnitude (e.g., Turbine RPM 0 - 8000, Throttle 0.0 - 1.0, and Heat 70 - 110°C) without curve flattening.
  • Stacked Lanes Mode (DAW / Profiler Style): Splits the dashboard into dedicated horizontal oscilloscope lanes, giving each variable its own unoccluded waveform track.
  • Interactive Cursor Inspection Card: Hover over any point on the graph timeline to inspect an instant floating card listing the exact numeric values of all active series at that timestamp.

3. Floating In-SceneView Telemetry HUD

  • In-Context Monitoring: Renders sleek, semi-transparent HUD cards directly above GameObjects in the SceneView via SceneView.duringSceneGui.
  • Live Status & Sparklines: Displays current values, threshold warning badges (pulsing red/orange on alert), and a 10-second compact sparkline waveform.
  • Pinning & Selection Modes: Enable ShowInSceneView = true on any [LiveTrack] attribute to pin HUDs permanently in SceneView, or toggle the toolbar button to display HUDs for selected objects.

4. Full C# Property & Method Support

  • Computed Properties: Place [LiveTrack] directly onto computed C# properties (e.g. public float SpeedKmh => rb.linearVelocity.magnitude * 3.6f;).
  • Seamless Inspector & Dashboard Integration: Renders sparklines, statistics, and alert thresholds identically for both serialized fields and dynamic properties.
ToolBox Vol. 1/Advanced Console Guides/Console Guide · Introduction to Advanced Console System

Console Guide · Introduction to Advanced Console System

The Advanced Console System is a professional, high-performance logging and debugging suite included in MSUltimate ToolBox Vol. 1. It acts as a centralized hub that aggregates logs, warnings, and errors from various subsystems (like Validation, HistoryTrack, and LiveTrack) as well as your custom user code.

Why Advanced Console?

Unity's built-in console is great for basic logging but often falls short when dealing with complex projects, requiring advanced filtering, real-time analytics, or proactive alerts. The Advanced Console System bridges this gap by offering:

  • Unified Log Registry: A single source of truth for all system events (RuntimeConsoleLogManager and MSConsole).
  • Rich Context: Every log entry can hold stack traces, context snapshots, tags, and quick-action buttons.
  • Visual Analytics: A timeline heatmap gives you a bird's-eye view of error density and system health over time.
  • Proactive Rules: Configure rules to automatically pause the editor or show popups when specific error thresholds are met.
  • Team Collaboration: Add user notes to log entries, bookmark critical logs, and save/export log sessions to share with your team.
  • Runtime Support: An automatic UI Toolkit in-game runtime console (RuntimeAdvancedConsoleUI) allows you to monitor logs and execute custom commands directly in your built game.

Key Features

1. The Advanced Console Window (UI Toolkit)

A highly optimized, dark-themed editor window built using UI Toolkit. It features:

  • Advanced Filtering: Filter by severity, source (User, Validation, LiveTrack, etc.), channels, and tags.
  • Smart Search: Supports both standard text matching and Regex.
  • Sidebar Navigation: Quickly toggle channels, sources, and active alert rules.
  • Detail Panel: Inspect selected logs to instantly view full stack traces, variable values at the time of the log (Context Snapshots), and execute Quick Actions (e.g., healing a player).

2. Runtime Overlay Console

Press the backtick (` `) key during Play Mode or in a built application to bring up the in-game UI Toolkit overlay console (RuntimeAdvancedConsoleUI`).

  • Captures Unity's internal Debug.Log messages.
  • Offers built-in commands like help, fps, time_scale, and clear.
  • Fully supports custom mapped commands using the [ConsoleCommand] attribute.

3. Deep Integration

The Advanced Console automatically captures events from other MSUltimate systems:

  • Validation Engine: Automatically logs validation errors and warnings.
  • HistoryTrack: Logs field value changes.
  • LiveTrack: Logs upper/lower bound alerts.

ToolBox Vol. 1/Advanced Console Guides/Console Guide · Getting Started with Advanced Console

Console Guide · Getting Started with Advanced Console

This guide will help you open, use, and integrate the Advanced Console System into your project.

1. Opening the Console Window

Inside the Unity Editor, open the Advanced Console Window from the top menu: Tools -> Maharaja Studio -> MSUltimate -> ToolBox Vol 1 -> Advanced Console

Tip: Dock this window alongside your standard Unity Console or Scene view. It serves as a superset of the built-in console for complex debugging.

2. Your First Log

You can log to the Advanced Console from any script using MSConsole (safe in both Editor and player builds with no #if UNITY_EDITOR required) or RuntimeConsoleLogManager:

csharp
using MaharajaStudio.MSUltimate.Runtime;
using UnityEngine;

public class MyScript : MonoBehaviour 
{
    void Start() 
    {
        MSConsole.Log("System initialized successfully!", channel: "Core", target: this);
    }
}

3. Enabling the Runtime Overlay

During gameplay (in Play Mode or in a build), RuntimeAdvancedConsoleUI loads automatically via RuntimeInitializeOnLoadMethod:

  1. Press Play (or run a build).
  2. Press the Backtick key (\`) (typically under the Escape key) to toggle the UI Toolkit console open and closed.

(Note: The legacy IMGUI RuntimeConsoleOverlay component is deprecated in favor of RuntimeAdvancedConsoleUI.)

4. Registering a Console Command

Console commands allow you to trigger methods from within the in-game runtime console.

csharp
using MaharajaStudio.MSUltimate.Runtime;
using UnityEngine;

public class PlayerController : MonoBehaviour
{
    public static float PlayerHealth = 100f;

    [ConsoleCommand("heal", "Restores the player's health to 100")]
    public static void HealPlayer()
    {
        PlayerHealth = 100f;
        Debug.Log("Player health restored!");
    }

    [ConsoleCommand("set_speed", "Sets the player's movement speed")]
    public static void SetSpeed(float speed)
    {
        // Add logic to set speed
        Debug.Log($"Speed set to {speed}");
    }
}

Open the runtime console ( ) and type heal or set_speed 15.5`.

ToolBox Vol. 1/Advanced Console Guides/Console Guide · Core Concepts

Console Guide · Core Concepts

Understanding the foundational pieces of the Advanced Console System allows you to leverage its full potential for debugging and analytics.

1. ConsoleLogEntry

Every event in the console is a ConsoleLogEntry. It holds significantly more data than a standard Unity log:

  • Severity: Trace, Debug, Info, Warning, Error, Critical.
  • Source: User, Validation, HistoryTrack, LiveTrack, System.
  • Channel: A string used to group logs (e.g., "Network", "Physics", "AI").
  • Tags: An array of strings for granular filtering.
  • TargetObject: A reference to the specific Unity Object (GameObject, ScriptableObject) that spawned the log. Clicking "Select Object" in the UI pings this object.
  • ContextSnapshot: A dictionary of string key-value pairs representing variables at the exact moment the log occurred.
  • Actions: A list of clickable buttons (ConsoleAction) embedded in the log detail view.

2. RuntimeConsoleLogManager (Registry)

The RuntimeConsoleLogManager (in MaharajaStudio.MSUltimate.Runtime.AdvancedConsole) is the static singleton that routes and stores all logs (and backs the MSConsole runtime API).

  • It maintains a circular buffer capped by MaxEntries (configured via RuntimeConsoleSettings) to prevent memory leaks.
  • It handles computing Collapse Hashes. If consecutive logs match by message and context, they are collapsed into a single entry with a badge count.
  • It provides APIs to run complex queries, filter logs, and manage Sessions.

3. Log Sessions & Exporting

You can take snapshots of the console's current state.

  • Start New Session: Resets the active view into a new logical block (useful when testing a specific feature).
  • Save Session: Stores the current log buffer into memory.
  • Compare Sessions: API available to diff two sessions and find unique or recurring errors.
  • Export: Export the current filtered view to CSV or JSON for external analysis or to attach to bug reports.

4. ConsoleRuleEngine

The Rule Engine evaluates every incoming log against a list of ConsoleLogRule definitions. A rule consists of:

  • Conditions: Min severity, specific source, regex pattern match, or occurring X times within Y seconds.
  • Actions: Show an Editor popup, pause the Editor immediately, or escalate the console log.

Example: If 5 Network errors happen in 1 second, the rule can automatically pause the Unity Editor so you can inspect the exact frame it failed.

5. Timeline Heatmap

Located just under the toolbar, the timeline converts the timestamps and severities of all logs in your current session into a stacked bar chart.

  • Green: Info logs.
  • Yellow: Warning logs.
  • Red: Error/Critical logs.

If your game suddenly stutters, you can look at the heatmap to see if a red "burst" of errors occurred at that exact moment.

ToolBox Vol. 1/Advanced Console Guides/Console Guide · How-To Guide

Console Guide · How-To Guide

This guide covers common advanced use cases for the Advanced Console System.

How to log Context Snapshots

When debugging complex AI or physics, knowing the state of specific variables at the moment of failure is critical.

csharp
using System.Collections.Generic;
using MaharajaStudio.MSUltimate.Runtime.AdvancedConsole;

var context = new Dictionary<string, string>
{
    { "Velocity", currentVelocity.ToString() },
    { "Grounded", isGrounded.ToString() },
    { "Target", currentTarget ? currentTarget.name : "None" }
};

RuntimeConsoleLogManager.Log(
    ConsoleLogSeverity.Warning, 
    ConsoleLogSource.User,
    "Player missed jump threshold",
    channel: "Physics",
    contextSnapshot: context,
    target: this.gameObject // Links the log to this GameObject
);

In the Console Window, click the log to see these values neatly formatted in the Detail Panel.

How to add Quick Actions to logs

Quick Actions are buttons embedded in a log's detail view. They are perfect for auto-fixing issues or teleporting to problem areas.

csharp
var actions = new List<ConsoleAction>
{
    new ConsoleAction("Auto-Fix Prefab", () => {
        // Run code to fix the issue
        ResetPrefabState();
    }),
    new ConsoleAction("Teleport to Error", () => {
        SceneView.lastActiveSceneView.pivot = this.transform.position;
    })
};

RuntimeConsoleLogManager.Log(
    ConsoleLogSeverity.Error, 
    ConsoleLogSource.User,
    "Navigation Node is corrupted.",
    actions: actions
);

How to search using regular expressions (Regex)

If you need to find specific patterns in your logs, use the Regex search.

  1. In the Advanced Console Window, click the .* (Regex Search) button in the toolbar.
  2. In the search box, enter your pattern.
    • Example ^\[Player\] finds logs that start with [Player].
    • Example Timeout|Disconnect finds logs containing either word.

How to add custom Runtime Console Commands

Ensure your method is public static and add the [ConsoleCommand] attribute.

csharp
using MaharajaStudio.MSUltimate.Runtime;

public class CheatManager
{
    [ConsoleCommand("give_gold", "Gives the player a specific amount of gold")]
    public static void GiveGold(int amount)
    {
        Player.Inventory.Gold += amount;
        // The return value (or Debug.Log) will be printed in the overlay console.
        UnityEngine.Debug.Log($"Granted {amount} gold."); 
    }
}

To use: open the runtime console ( ) and type give_gold 500`.

How to Bookmark and Annotate Logs

During a playtest, you might notice odd behavior that doesn't trigger an error.

  1. Find a log representing that moment.
  2. Click the Star () icon next to the log to Bookmark it.
  3. Select the log and scroll down in the Detail Panel to the Note: text box.
  4. Type your observations (e.g., "Player clipped through floor here").
  5. Use the Star icon in the main toolbar to filter only your bookmarked logs when you finish testing.

ToolBox Vol. 1/Integration Attributes/[ConsoleCommand]

[ConsoleCommand]

Registers static C# methods as invokable developer console commands within the Advanced Runtime Console overlay.

1. Overview & Value Proposition

What it does: [ConsoleCommand] automatically discovers and registers static C# methods into the runtime Advanced Console system. By decorating any static method with [ConsoleCommand], developers, QA testers, and designers can invoke gameplay cheats, toggle debug visualization modes, manipulate game speed, or spawn items directly by typing commands into the runtime HUD console.

The Problem: Building an in-game developer console usually involves creating complex custom command dictionaries, maintaining fragile string-to-method dispatchers, parsing arguments manually, and hardcoding autocomplete tables. When code is refactored, these bespoke dispatch tables fall out of sync, leading to broken cheats and frustrating debugging sessions during QA passes.

The Solution: Decorating static methods with [ConsoleCommand]:

  • Zero-Boilerplate Registration: Automatically indexes methods via reflection without any central registry or manager script setup.
  • Categorization & Autocomplete: Organizes commands into clean categories (Category = "Combat", Category = "Cheats") with fuzzy autocomplete in the console GUI.
  • Usage Syntax Hints: Supply clear syntax guides (Usage = "give_gold <amount>") rendered in the console help menu.
  • Automatic Parameter Conversion: Console parser automatically deserializes string arguments into primitive types (int, float, bool, string, Vector3).

2. Quick Start

csharp
using UnityEngine;
using MaharajaStudio.MSUltimate.Runtime;

public static class DebugCommands
{
    [ConsoleCommand("heal_player", "Restores the local player to full health.", Category = "Player")]
    public static void HealPlayer()
    {
        Debug.Log("Player restored to full health.");
    }
}

ToolBox Vol. 1/Integration Attributes/[HistoryTrack]

[HistoryTrack]

Records discrete serialized field mutations over time, persisting values, timestamps, usernames, and call stacks into an undo timeline.

1. Overview & Value Proposition

What it does: [HistoryTrack] records changes made to a field or property over time, capturing the new value, previous value, timestamp, modifying user, and optional script call stack. Changes are visualized directly below the field via an inline interactive timeline bar (ShowInlineTimeline) or step graph (ShowInlineGraph), and are persisted to disk across recompiles and editor restarts.

The Problem: Balancing game economy or tuning complex physics requires constant iterative adjustments. When a weapon balance tweak or level variable is inadvertently broken, developers and designers struggle to answer basic diagnostic questions: "Who changed this value?", "What was this set to yesterday before the recompile?", and "Which script modified this at runtime?". Standard Unity offers only a volatile Undo.RecordObject buffer that disappears upon editor restart or domain reload.

The Solution: Decorating fields or properties with [HistoryTrack]:

  • Persistent Change Audit Trail: Persists value deltas, timestamps, and author usernames across editor sessions to disk in JSON format (PersistAcrossSessions = true).
  • Inline Timeline & Step Graph: Renders a scrubbable mini-timeline directly beneath the property in the Inspector (ShowInlineTimeline = true).
  • Team Accountability & Collaboration: Tracks the OS username of modifying developers (TrackUser = true), designates owners (OwnerName), and provides change reason prompts (RequireReason = true).
  • Field Locking & Policy Governance: Lock critical parameters against accidental edits (IsLocked = true, LockedBy = "LeadDesigner"), or restrict editing to specific teammates (AllowedEditors = "Alice, Bob").
  • Regression & Boundary Alerts: Notifies developers if a value reverts to a previous regression state (AlertOnRevert = true) or breaches threshold limits (ExpectedMin, ExpectedMax).

2. Quick Start

csharp
using UnityEngine;
using MaharajaStudio.MSUltimate.Runtime;

public class WeaponBalanceData : MonoBehaviour
{
    [HistoryTrack(
        ColorHex = "#e67e22",
        ShowInlineTimeline = true,
        OwnerName = "Soutick",
        MaxEntries = 50)]
    public float baseDamage = 45f;
}

[LiveTrack]

Tracks continuous field values over time and renders an inline real-time sparkline graph, statistical telemetry, and threshold alert badges.

1. Overview & Value Proposition

What it does: [LiveTrack] instruments numeric fields and properties (float, int, Vector3.magnitude, etc.) to sample values continuously at a configurable frequency (SampleRate). It renders an interactive, real-time animated sparkline graph directly in the Inspector or Scene View, complete with running statistical metrics (ShowStats: Current, Δ, Min, Max, Average, and Rate of change) and visual boundary alert notifications (AlertBelow, AlertAbove).

The Problem: Watching numerical behavior in Unity during Play Mode (such as player velocity, AI suspicion levels, health decay, or frame time delta) requires writing throwaway Debug.Log() spam or opening cumbersome external profilers. Log lines scroll away rapidly and provide zero sense of trend, frequency, or wave oscillation, while Unity's native Animation Window requires tedious recording workflows.

The Solution: Decorating fields or properties with [LiveTrack]:

  • Real-Time Inline Graphing: Renders a high-frequency sparkline waveform directly below the field in the Inspector (ShowGraph = true, GraphHeight = 60f).
  • Live Statistical Dashboard: Displays key live analytics including Min, Max, Mean Average, and instantaneous delta rate (ShowStats = true).
  • Threshold Limit Alarms: Flashes high-visibility visual alert badges when values drop below minimum safety limits (AlertBelow) or spike beyond ceilings (AlertAbove).
  • Flexible Tracking Modes: Track in EditMode, PlayMode, or Both (TrackingMode = LiveTrackMode.Both).
  • Session Recording & Snapshots: Capture baseline comparison snapshots (EnableSnapshots = true) and record telemetry sessions for later review (RecordSession = true).

ToolBox Vol. 1/Integration Attributes/[TrackLifetime]

[TrackLifetime]

Tracks instantiate, destroy, and object pooling lifecycle events for components to identify memory leaks and allocation spikes.

1. Overview & Value Proposition

What it does: [TrackLifetime] instruments component classes to automatically record lifecycle telemetry: instantiation timestamps, active duration, destruction events, and object pool recycle cycles (OnEnable/OnDisable). All tracked instances are monitored in real-time within the Lifetime Track window, with alerts for leaked long-lived instances (LongLifespanThreshold) and excessive concurrent population spikes (PeakAlertThreshold).

The Problem: Object pooling bugs, lingering references, and runaway GameObject.Instantiate() loops are among the most common sources of memory fragmentation and garbage collection stutters in Unity. Standard Unity profilers show generic memory counters without correlating which game subsystem, spawning script, or pooling manager created the unreleased instances.

The Solution: Decorating classes with [TrackLifetime]:

  • Automated Lifecycle Profiling: Measures instance lifetimes from birth to death without writing manual profiling hooks.
  • Pooling & Recycle Metrics: Toggle IsPooled = true to measure spawn/recycle frequencies through OnEnable and OnDisable rather than standard garbage creation.
  • Spawn Source Stack Tracing: Captures exact C# call stacks at the moment of creation (TrackSpawnSource = true), pinning down exactly which spawner created each object.
  • Peak Population & Leak Guards: Triggers immediate alerts when concurrent instances exceed limits (PeakAlertThreshold = 100) or linger beyond intended lifespans (LongLifespanThreshold = 30f).
  • Visual Grouping & Category Tints: Organize types into distinct categories (Category = "Enemies", Category = "Projectiles") with custom color coding (ColorHex).

6. Real-World Production Example

csharp
using UnityEngine;
using MaharajaStudio.MSUltimate.Runtime.LifetimeTracker;

namespace ProjectZero.Weapons
{
    // High-frequency pooled projectile monitored for pool leaks and allocation surges
    [TrackLifetime("Projectiles", "#3498DB",
        IsPooled = true,
        MaxHistory = 5000,
        LongLifespanThreshold = 10.0f,    // Flag projectile if it survives > 10 seconds without despawning
        PeakAlertThreshold = 300,         // Alert if active projectile count breaches 300
        TrackSpawnSource = true,
        LogToConsole = true)]
    public class KineticBullet : MonoBehaviour
    {
        public float damage = 15f;
        public float lifetime = 3.0f;

        private float _aliveTimer;

        private void OnEnable()
        {
            _aliveTimer = 0f;
        }

        private void Update()
        {
            _aliveTimer += Time.deltaTime;
            if (_aliveTimer >= lifetime)
            {
                gameObject.SetActive(false); // Return to pool
            }
        }
    }
}
